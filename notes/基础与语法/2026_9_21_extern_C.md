# `extern "C"` 学习笔记

## 1. 核心作用

`extern "C"` 是 C++ 的语言链接规范，告诉 C++ 编译器：

> 这个函数或变量使用 C 语言的链接方式，不使用 C++ 的名称修饰。

它主要用于 C 和 C++ 混合编程、静态库/动态库接口以及对外提供稳定的 C 风格 API。

## 2. 为什么需要它

C++ 支持函数重载，因此编译器会根据函数名、参数类型等信息修改符号名，这叫“名称修饰”（Name Mangling）。

```cpp
int add(int, int);
double add(double, double);
```

这两个函数在 C++ 中需要被区分；而 C 不支持函数重载，C 编译器通常直接导出名为 `add` 的符号。

如果 C 文件提供了 `add`，C++ 文件直接声明并调用它，C++ 可能会寻找名称修饰后的符号，最终导致链接错误。

## 3. 基本写法

声明单个函数：

```cpp
extern "C" int add(int a, int b);
```

直接定义：

```cpp
extern "C" int add(int a, int b) {
    return a + b;
}
```

一次声明多个函数：

```cpp
extern "C" {
    int add(int a, int b);
    int subtract(int a, int b);
}
```

## 4. C/C++ 共用头文件的写法

`extern "C"` 是 C++ 语法，C 编译器不认识，所以要使用 `__cplusplus` 做条件编译：

```c
#ifndef MATH_API_H
#define MATH_API_H

#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);
int subtract(int a, int b);

#ifdef __cplusplus
}
#endif

#endif
```

- 用 C 编译时，`__cplusplus` 未定义，会忽略 `extern "C"`。
- 用 C++ 编译时，`__cplusplus` 已定义，会使用 C 链接方式。

## 5. `extern` 和 `extern "C"` 的区别

```cpp
extern int globalValue;
```

普通 `extern` 表示变量在其他源文件中定义，这里只是声明。

```cpp
extern "C" int add(int, int);
```

`extern "C"` 主要表示使用 C 的名称和链接规则。

可以简单记忆：

```text
extern       ：定义在别处
extern "C"   ：按照 C 的方式链接
```

## 6. 它不会把 C++ 代码变成 C 代码

```cpp
extern "C" int add(int a, int b) {
    int result = a + b;
    return result;
}
```

这段函数仍然由 C++ 编译器编译，只是导出的函数名采用 C 的链接方式。

## 7. 对外 C 接口的注意事项

如果希望 C 代码调用 C++ 提供的接口，通常只暴露 C 能理解的类型，例如：

```cpp
extern "C" int add(int a, int b);
extern "C" void process(int* data, int size);
```

接口中应尽量避免直接暴露：

- `std::string`
- `std::vector`
- C++ 类对象
- 模板类型
- C++ 重载函数
- C++ 异常

`extern "C"` 主要解决名称修饰和链接方式问题，不能自动解决所有 ABI、调用约定、结构体布局以及内存分配/释放问题。

## 8. 记忆结论

```cpp
extern "C"
```

可以理解为：

> 这个接口由 C++ 编译，但按照 C 的函数名和链接规则提供给外部使用。
