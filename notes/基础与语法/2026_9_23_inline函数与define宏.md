# `inline` 函数与 `#define` 宏

## 一、先记住结论

- `inline` 修饰的是普通 C++ 函数；`#define` 定义的是预处理器宏，本质上是编译前的文本替换。
- 普通功能优先写函数。函数有类型检查，传入的参数只求值一次；宏可能重复展开参数，容易产生错误。
- `inline` 不保证编译器一定展开函数。它还有一个常见用途：允许相同的函数定义出现在多个 `.cpp` 编译单元中，例如把短函数定义写在头文件里。

## 二、宏是怎样替换文本的

```cpp
#define SQUARE(x) ((x) * (x))

int result = SQUARE(3);
```

预处理器会把 `SQUARE(3)` 替换成 `((3) * (3))`。宏没有真正的函数参数，也不会像普通函数那样检查参数类型。

宏参数如果带有副作用，展开后可能执行多次：

```cpp
int i = 1;
int result = SQUARE(i++);
```

替换后相当于 `((i++) * (i++))`。这里 `i++` 被放进表达式两次，而且两个修改没有规定先后顺序，因此行为未定义。不要这样使用宏。

宏也容易遇到运算优先级问题：

```cpp
#define DOUBLE(x) x * 2
int result = DOUBLE(3 + 1); // 展开为 3 + 1 * 2，结果是 5
```

给参数和整个表达式都加括号能减少优先级问题，但不能解决宏缺少函数语义、参数可能被重复求值等问题。

## 三、`inline` 仍然是普通函数

```cpp
inline int square(int x) {
    return x * x;
}

int i = 1;
int result = square(i++); // i++ 只作为实参求值一次
```

编译器会像检查普通函数一样检查参数和返回值。`inline` 不改变函数的调用方式和计算结果。现代编译器会自行决定是否展开函数调用，所以 `inline` 不是“强制展开”。

## 四、为什么头文件里的函数有时要写 `inline`

假设 `math.h` 定义了一个函数：

```cpp
// math.h
int doubleValue(int x) {
    return x * 2;
}
```

如果 `main.cpp` 和 `a.cpp` 都写了 `#include "math.h"`，头文件内容会分别进入这两个 `.cpp` 文件。两个文件都因此定义了 `doubleValue`，最后链接时通常会报重复定义。

把头文件中的函数定义标记为 `inline`：

```cpp
// math.h
inline int doubleValue(int x) {
    return x * 2;
}
```

C++ 允许相同的 `inline` 函数定义出现在多个 `.cpp` 编译单元中。这里 `inline` 的重点是允许这种多处定义，不是保证优化器展开函数。各处定义需要保持一致。

如果函数定义只放在一个 `.cpp` 文件中，通常不需要 `inline`。初学阶段可以先把函数当普通函数使用；学到头文件和多文件编译时，再理解这个用途。

## 五、头文件保护和 `inline` 的区别

```cpp
#ifndef MATH_H
#define MATH_H

inline int doubleValue(int x) {
    return x * 2;
}

#endif
```

- 头文件保护（`#ifndef` / `#define` / `#endif`）防止同一个 `.cpp` 文件在一次编译中重复包含头文件。
- `inline` 允许相同函数定义出现在多个 `.cpp` 编译单元中。

两者解决的是不同问题，头文件保护不能代替 `inline`。

## 六、快速对比

| 对比 | `inline` 函数 | `#define` 宏 |
|---|---|---|
| 本质 | 普通 C++ 函数 | 预处理器文本替换 |
| 类型检查 | 有 | 没有函数参数类型检查 |
| 参数求值 | 每个实参正常求值一次 | 展开后可能重复求值 |
| 作用域 | 遵循 C++ 规则 | 从宏定义处生效，直到取消定义或文件结束 |
| 典型用途 | 普通小函数、头文件函数定义 | 条件编译等预处理器工作 |

记忆方法：需要封装普通功能时用函数；需要预处理器按条件控制代码时才考虑宏。
