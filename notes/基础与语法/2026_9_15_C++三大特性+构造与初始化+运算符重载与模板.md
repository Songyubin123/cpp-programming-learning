# C++ 三大特性与相关基础学习笔记

整理日期：2026-09-15  
范围：本次聊天中的封装、继承、多态，以及构造函数、初始化列表、析构函数、运算符重载和模板。

> 阅读顺序：类与成员 → 封装 → 构造与初始化 → 继承 → 虚函数与析构 → 多态 → 运算符重载与模板。

## 1. 类、对象、成员、子类

- **类**：描述一类对象有哪些数据和功能，例如 `Dog`。
- **对象**：根据类创建的具体实例，例如 `Dog dog;` 中的 `dog`。
- **成员变量**：类中保存数据的变量，例如 `name`、`age`。
- **成员函数**：类中提供行为的函数，例如 `speak()`。
- **父类 / 基类**：被继承的已有类，例如 `Animal`。
- **子类 / 派生类**：通过继承创建的类，例如 `Dog`。

```cpp
class Dog {
public:
    int age = 0;           // 成员变量
    void speak() const {} // 成员函数
};
```

## 2. 封装：隐藏内部实现，提供使用接口

封装把数据和操作数据的函数放在一起，并通过访问权限控制外部如何使用对象。

| 成员权限 | 本类成员函数 | 子类成员函数 | 类外普通代码 |
|---|---|---|---|
| `public` | 可访问 | 可访问 | 可访问 |
| `protected` | 可访问 | 可访问，但有访问规则限制 | 不可直接访问 |
| `private` | 可访问 | 不可直接访问 | 不可直接访问 |

上表先按公有继承理解，暂不展开友元等特殊情况。子类可以访问自身继承来的 `protected` 成员，但并不意味着能通过任意父类对象访问受保护成员。

```cpp
class Person {
private:
    int age = 0;

public:
    void setAge(int value) {
        if (value >= 0) {
            age = value;
        }
    }

    int getAge() const {
        return age;
    }
};
```

外部通过 `setAge()` 和 `getAge()` 使用年龄数据，不能直接修改 `age`。

**好处**：集中检查数据、减少误用；只要接口及其约定保持兼容，内部实现通常可以调整而不要求调用者改代码。这里的“安全”主要指减少程序误用，不是数据加密或安全隔离。

## 3. 构造函数：创建对象时完成初始设置

构造函数在创建对象时自动调用：

- 名字与类名相同。
- 没有返回类型，连 `void` 都不写。
- 可以接收参数。

```cpp
class Dog {
public:
    std::string name;

    Dog(std::string n) : name(n) {}
};

// 使用时：
Dog dog("小黑");
```

这里 `n` 是构造函数接收数据的参数，`name` 是对象中保存数据的成员。使用 `std::string` 时需要包含 `<string>`。

## 4. 成员初始化列表与 `{}`

```cpp
Dog(std::string n) : name(n) {}
```

拆开理解：

| 部分 | 含义 |
|---|---|
| `Dog(std::string n)` | 构造函数接收字符串参数 `n` |
| `: name(n)` | 初始化列表：用 `n` 初始化成员 `name` |
| `{}` | 构造函数体：初始化后要执行的代码 |

多个初始化项用逗号隔开：

```cpp
Dog(std::string n, int a) : name(n), age(a) {
    std::cout << "创建完成\n";
}
```

### 初始化与赋值的区别

```cpp
// 直接用 n 初始化 name
Dog(std::string n) : name(n) {}

// name 先默认初始化为空字符串，再在函数体中赋值
Dog(std::string n) {
    name = n;
}
```

上面是两种备选写法，不能同时放进同一个类中作为相同签名的构造函数。

**初始化**是设置初始值；**赋值**是修改一个已经存在的变量的值。

推荐初始化列表的原因：

1. 直接表达初始状态，避免某些类型先默认构造再赋值的操作。
2. 有些成员需要在初始化阶段设置，例如没有其他初始值的 `const` 成员、引用成员，以及没有可用默认构造函数的成员对象。
3. 实际性能收益取决于成员类型和编译器优化，不能一概而论。

```cpp
class Item {
    const int id;

public:
    Item(int n) : id(n) {} // 正确：初始化 const 成员
};
```

### `{}` 有什么用？

用于执行初始化完成后的其他操作，例如打印、检查或执行额外逻辑。即使函数体为空，初始化列表也已经完成了工作。

普通单继承场景下，顺序是：

```text
初始化父类部分 → 按成员声明顺序初始化成员 → 执行构造函数体
```

成员实际按它们在类中的**声明顺序**初始化，不按初始化列表的书写顺序；书写时也应保持一致。

## 5. 继承：复用父类，并形成更具体的类型

```cpp
class Dog : public Animal {
    // Dog 是 Animal 的派生类
};
```

公有继承通常表达“是一种”的关系：狗是一种动物。

### 两个位置的 `public`

```cpp
class Animal {
public: // 成员访问权限：下面的成员对外公开
    void eat() {}
};

class Dog : public Animal {}; // 继承方式：公有继承

Dog dog;
// 在函数中调用：dog.eat();
```

**公有继承保留父类公开接口的可见性，不会把父类所有成员变成公开成员。**它也允许把子类对象通过父类引用或指针使用。

### 三种继承方式

| 父类成员原权限 | `public` 继承后 | `protected` 继承后 | `private` 继承后 |
|---|---|---|---|
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | 子类不可直接访问 | 子类不可直接访问 | 子类不可直接访问 |

**父类的私有数据仍然存在于子类对象的父类部分中，只是子类不能直接访问。**可以通过父类允许使用的接口间接操作。

### `Dog(std::string n) : Animal(n) {}` 如何执行？

假设父类构造函数是：

```cpp
Animal(std::string n) : name(n) {}
```

子类构造函数是：

```cpp
Dog(std::string n) : Animal(n) {}
```

执行 `Dog dog("小黑");` 时：

```text
Dog 的参数 n 收到 "小黑"
    ↓
Animal(n)：把名字传给父类构造函数
    ↓
name(n)：父类负责初始化自己的 name 成员
    ↓
执行 Animal 的构造函数体
    ↓
执行 Dog 的构造函数体
```

- `name(n)` 初始化成员变量。
- `Animal(n)` 初始化同一个对象中的父类部分，不是额外创建一个独立对象。
- 两个构造函数中的 `n` 是各自独立的参数，只是同名。

## 6. `virtual`、函数后的 `const`、`override`

```cpp
// 父类
virtual void speak() const;

// 子类
void speak() const override;
```

| 语法 | 作用 |
|---|---|
| `virtual` | 声明虚函数，支持按实际对象类型选择实现 |
| `void` | 函数不返回值 |
| `speak()` | 函数名和参数列表 |
| 函数后的 `const` | 不通过当前对象修改其普通成员，并允许常量对象调用 |
| `override` | 要求编译器检查是否正确重写了父类虚函数 |

### `const` 成员函数

```cpp
void speak() const {
    std::cout << name; // 可以读取
    // name = "小白"; // 不可修改普通成员
}
```

这里的 `const` 不是修饰返回值，也不保证函数完全没有副作用：它可以打印输出；`mutable` 成员等特殊情况暂不展开。

### 为什么 `override` 写在后面？

这是 C++ 规定的语法位置：写在函数声明的后部，在这里位于 `const` 之后、函数体之前。

- 父类函数必须是虚函数，子类才能对它使用 `override`。
- 子类正确重写后仍然是虚函数，不必再次写 `virtual`。
- `override` 负责检查，不是多态的开关；通常推荐保留。
- 父类的 `speak() const` 与子类的 `speak()` 不匹配；加上 `override` 后编译器会指出错误。
- 普通同名成员函数不一定是重写，还可能涉及名字隐藏，不能把所有同名函数都叫 `override`。

## 7. 析构函数：销毁对象时清理

```cpp
virtual ~Animal() = default;
```

拆开理解：

- `~Animal()`：析构函数，类名前加 `~`，在对象销毁时执行清理。
- `= default`：明确要求编译器生成默认实现，例如销毁字符串成员。
- `virtual`：允许通过父类指针删除子类对象时，正确执行完整的析构过程。

```cpp
Animal* animal = new Dog("小黑");
delete animal;
```

当父类具有虚析构函数时，析构过程先处理 `Dog` 部分，再处理 `Animal` 部分。

对于这里的普通删除方式，如果父类析构函数不是虚函数，通过 `Animal*` 删除实际的 `Dog` 对象会产生未定义行为。

**默认析构不等于什么都不做。构造负责初始设置，析构负责销毁清理。**

## 8. 多态：统一调用，各自表现

多态可以理解为：同样调用 `speak()`，狗发出“汪汪”，猫发出“喵喵”。

| 类别 | 常见方式 | 核心理解 |
|---|---|---|
| 编译时多态 | 函数重载、运算符重载、模板 | 根据编译时信息选择或生成相应代码 |
| 运行时多态 | 虚函数重写 | 通过父类指针或引用，按实际对象类型选择实现 |

### 完整示例

下面代码可以作为独立 `.cpp` 文件编译运行，使用 C++11 或更新标准。

```cpp
#include <iostream>
#include <string>

class Animal {
protected:
    std::string name;

public:
    Animal(std::string n) : name(n) {}
    virtual ~Animal() = default;

    virtual void speak() const {
        std::cout << name << "发出声音\n";
    }
};

class Dog : public Animal {
public:
    Dog(std::string n) : Animal(n) {}

    void speak() const override {
        std::cout << name << "：汪汪！\n";
    }

    void wagTail() const {
        std::cout << name << "摇尾巴\n";
    }
};

class Cat : public Animal {
public:
    Cat(std::string n) : Animal(n) {}

    void speak() const override {
        std::cout << name << "：喵喵！\n";
    }
};

void makeSound(const Animal& animal) {
    animal.speak();
}

int main() {
    Dog dog("小黑");
    Cat cat("小白");

    makeSound(dog);
    makeSound(cat);
}
```

输出：

```text
小黑：汪汪！
小白：喵喵！
```

`makeSound()` 只需要知道参数具有动物接口，具体发声行为由实际对象决定。子类没有重写某个虚函数时，沿用继承来的实现。

### 为什么用指针或引用？

```cpp
void makeSound(const Animal& animal); // 引用原对象，保留实际类型
```

这里的 `const` 表示不通过引用修改对象；`&` 表示引用，不复制对象。

如果改为按值接收：

```cpp
void makeSound(Animal animal) {
    animal.speak();
}
```

传入 `Dog` 时，只复制其中的 `Animal` 部分，形成独立的 `Animal` 对象。这叫**对象切片**；在上述示例中会调用 `Animal::speak()`。

## 9. 静态类型与动态类型：本次重点疑问

> 静态类型看代码声明及表达式本身，动态类型看实际对象。

```cpp
Dog dog("小黑");
Animal& animal = dog;
```

没有创建新的动物，也没有把狗变成其他类型。`animal` 引用的仍然是原来的狗。

| 观察对象 | 类型 |
|---|---|
| 引用变量 `animal` 的声明类型 | `Animal&` |
| 表达式 `animal` 的静态类型 | `Animal` |
| 该表达式所指对象的动态类型 | `Dog` |

如果声明为 `const Animal&`，表达式的静态类型则是 `const Animal`；引用所指的完整对象仍然是 `Dog`。

### 两种类型各管什么？

```cpp
animal.speak();     // 正确：Animal 有此接口；虚调用执行 Dog 版本
// animal.wagTail(); // 错误：Animal 没有 wagTail 成员
dog.wagTail();      // 正确：通过 Dog 类型使用狗特有的功能
```

1. **静态类型**决定编译时成员查找、访问检查和重载选择等。
2. **动态类型**决定虚调用最终执行哪个重写版本。

如果父类的 `speak()` 不是虚函数，通过父类引用进行上述调用时，选择父类版本；子类也不能再为它标注 `override`。

### 指针也一样

```cpp
Animal* p = &dog;
p->speak(); // 狗的版本

p = &cat;
p->speak(); // 猫的版本
```

- `p` 的声明类型一直是 `Animal*`。
- `*p` 所指对象的动态类型，先是 `Dog`，后是 `Cat`。
- 改变的是指向哪个对象，不是狗变成猫。
- “动态类型”不代表对象的类型必须变化，也不代表必须使用 `new`。

**速记：静态类型决定可使用的接口，动态类型决定虚函数的具体版本。**

## 10. vtable 与 vptr：常见底层实现

C++ 标准规定虚函数的行为，但不要求编译器必须使用虚函数表。下面是简单单继承场景的常见模型。

- **vtable（虚函数表）**：包含用于定位虚函数实现的表项。
- **vptr（虚表指针）**：对象内部用于找到对应虚函数表的隐藏指针。

```text
dog 对象中的 vptr → Dog 的虚函数表 → speak 表项 → Dog::speak()
cat 对象中的 vptr → Cat 的虚函数表 → speak 表项 → Cat::speak()
```

通过父类指针或引用调用虚函数时，可以把过程理解为：找到实际对象 → 找到虚函数表 → 读取对应表项 → 调用函数。

在这个简化模型中，同类对象共享虚函数表，每个对象保存自己的虚表指针。**“每个类恰好一张表、每个对象恰好一个指针”不是普遍规则**；多重继承可能更复杂，编译器也可能在知道目标时优化掉查表。

## 11. 函数重载：同名函数处理不同参数

```cpp
void print(int value) {
    std::cout << "整数\n";
}

void print(double value) {
    std::cout << "小数\n";
}

// 在函数中调用：
// print(10);   // 选择 int 版本
// print(3.14); // 选择 double 版本
```

重载根据参数列表等信息区分，不能只靠返回类型不同来重载。**重载与继承中的虚函数重写是不同概念。**

## 12. 运算符重载：为自定义类型定义运算行为

例如，让两个坐标能使用 `+` 相加：

```cpp
class Point {
public:
    int x;
    int y;

    Point(int a, int b) : x(a), y(b) {}

    Point operator+(const Point& other) const {
        return Point(x + other.x, y + other.y);
    }
};

// 使用时：
Point a(1, 2);
Point b(3, 4);
Point c = a + b; // c 为 (4, 6)
```

### 为什么 `b` 充当 `other`？

这里的 `operator+` 是成员函数：

```cpp
a + b
// 在本例中等价于：
a.operator+(b)
```

按 `对象.函数(参数)` 理解：

- `a` 是调用函数的当前对象。
- `b` 是传入的参数，绑定到引用参数 `other`。
- `other` 只是参数名，可以改成 `rhs` 等其他名字。

| 函数内部写法 | 本次调用对应的数据 |
|---|---|
| `x` / `y` | `a.x` / `a.y` |
| `other.x` / `other.y` | `b.x` / `b.y` |

如果是 `b + a`，对应 `b.operator+(a)`，这时 `other` 引用的是 `a`。

### 两个 `const`

```cpp
Point operator+(const Point& other) const;
```

- 参数中的 `const`：不通过 `other` 修改右侧对象。
- 末尾的 `const`：不通过当前对象修改左侧对象的普通成员。
- 返回类型 `Point`：返回一个新坐标对象。

运算符重载本质上是函数，但上述左右操作数的对应方式针对的是这个**成员运算符函数**。运算符也可以用非成员函数重载。不能创造新运算符，也不能改变既有运算符的优先级。

## 13. 模板：把类型变成可替换的部分

### 函数模板

整数和小数求较大值，算法相同，可以写成一份模板：

```cpp
template <typename T>
T larger(T a, T b) {
    return a > b ? a : b;
}
```

- `T` 是类型占位符。
- `template <typename T>` 声明一个类型模板参数。
- `a > b ? a : b` 表示：条件成立选 `a`，否则选 `b`。

```cpp
larger(3, 5);           // T 推导为 int，返回 5
larger(2.5, 1.8);       // T 推导为 double，返回 2.5
larger<double>(3, 5.5); // 显式指定 double，返回 5.5
```

编译器根据具体类型形成所需的函数版本，称为**模板实例化**。

对于这个模板，直接写 `larger(3, 5.5)` 会因两个参数推导出不同的 `T` 而失败；可以像上面那样显式指定类型。类型也必须支持函数使用的操作，例如这里的 `>` 比较。

### 类模板

```cpp
template <typename T>
class Box {
public:
    T value;
    Box(T v) : value(v) {}
};

Box<int> a(10);
Box<double> b(3.14);
```

`Box<int>` 保存整数，`Box<double>` 保存小数。常见的 `std::vector<int>`、`std::vector<double>` 也是类模板的应用，使用时需要包含 `<vector>`。
