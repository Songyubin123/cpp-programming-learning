# 链表知识总结

结合 9 月 7 日至 10 日的练习：链表创建、移除元素、设计链表、反转链表、删除倒数第 n 个节点、相交链表和环形链表。

链表题的重点是：**知道指针当前指向谁，修改连接前保留需要的节点，明确循环结束时指针应停在哪里。**

## 1. 节点、指针和链表

```cpp
struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int x) : val(x), next(nullptr) {}
};
```

- 节点包含数据 `val` 和指向下一个节点的指针 `next`。
- `head` 保存头节点的地址；空链表的 `head == nullptr`。
- 普通无环单链表的最后一个节点满足 `next == nullptr`。
- 节点不要求在内存中连续，遍历依靠 `next`，不能靠指针加一寻找下一个节点。
- 单链表只有后继指针；双向链表还保存前驱指针；循环链表的末尾会连接回已有节点。

几个容易混淆的表达式：

| 表达式 | 含义 |
| --- | --- |
| `ListNode node(1)` | 创建节点对象 |
| `ListNode* p = &node` | p 保存 node 的地址 |
| `p = p->next` | 移动指针 p，不改变节点之间的连接 |
| `p->next = q` | 修改 p 所指节点的后继连接 |
| `p == q` | 两个指针是否相等；都非空时表示指向同一节点 |
| `p->val == q->val` | 节点值是否相等，要求 p、q 都指向有效节点 |

`ListNode* cur = head` 只复制地址。移动 `cur` 不会移动 `head`，但通过 `cur` 修改节点，其他指向同一节点的指针也会看到变化。

## 2. 遍历与虚拟头节点

遍历普通无环链表：

```cpp
for (ListNode* cur = head; cur != nullptr; cur = cur->next) {
    std::cout << cur->val << ' ';
}
```

这比连续写多次 `head->next->next` 更适合打印长度会变化的链表。有环时不能直接使用这种遍历方式，否则不会结束。

虚拟头节点放在真正头节点之前：

```text
dummy → 第一个节点 → 第二个节点 → nullptr
```

```cpp
ListNode dummy(0);
dummy.next = head;
ListNode* prev = &dummy;
```

它不计入链表长度，`val` 通常无实际含义。它让原头节点也有前驱，便于统一处理头部和中间的插入、删除。最终返回 `dummy.next`，不能返回 `&dummy`。

## 3. 插入和删除：先找前驱

已知有效的前驱节点 `prev`，在其后插入一个新节点：

```cpp
ListNode* node = new ListNode(value);
node->next = prev->next;  // 先连接原来的后半段
prev->next = node;        // 再把新节点接入链表
```

这两步不能直接颠倒。否则第二步可能让 `node->next` 指向自己，还会丢失原后继连接。

已知 `prev->next` 存在，删除其后的节点：

```cpp
ListNode* removed = prev->next;
prev->next = removed->next;
delete removed;  // 前提：该节点由 new 创建，并由这里负责释放
```

`delete` 后不能再读取 `removed->next`。把一个指针设为 `nullptr` 不会释放内存，也不会把其他指向该节点的指针自动清空。

移除所有指定值时，删除 `cur->next` 后应继续检查新的 `cur->next`；只有没有删除时才移动 `cur`，否则会漏掉连续的目标节点。

设计链表类时还要维护长度：插入成功后加一，删除成功后减一。查询和删除的索引范围是 `0 <= index < size`，插入允许 `index == size`。9 月 8 日练习的题意还规定负插入索引按 0 处理，这属于题目约定。

## 4. 反转链表：保留后继，再改变方向

三个指针分别表示已经反转部分的头、当前节点、尚未处理的后继：

```cpp
ListNode* pre = nullptr;
ListNode* cur = head;
while (cur != nullptr) {
    ListNode* temp = cur->next;
    cur->next = pre;
    pre = cur;
    cur = temp;
}
// pre 是新头节点
```

循环中，`pre` 指向已经反转好的部分，`cur` 指向还没处理的部分。先保存 `temp`，才能在断开原连接后继续处理后续链表。空链表直接得到 `nullptr`。

当前递归版本定义为 `reverse(ListNode* pre, ListNode* cur)`，下一层必须调用 `reverse(cur, temp)`，入口为 `reverse(nullptr, head)`。旧心得中出现的 `reverse(temp, cur)` 使用了另一种参数顺序，不能直接套进当前函数。

把状态通过参数传递，可以避免未重置的成员变量保留上次调用结果。迭代和递归都需要 `O(n)` 时间；迭代额外空间为 `O(1)`，递归为 `O(n)`，不能默认编译器一定会优化递归调用栈。

## 5. 删除倒数第 n 个节点：保持固定间距

当前实现采用以下约定，前提是 `1 <= n <= 链表长度`：

1. `fast` 和 `slow` 都从 `dummy` 出发。
2. `fast` 先走 n 步，让两个指针相隔 n 条连接。
3. 两者每轮各走一步，直到 `fast->next == nullptr`。
4. 此时 `fast` 是尾节点，`slow` 是待删除节点的前驱，删除 `slow->next`。

例如 `dummy → 1 → 2 → 3 → 4 → 5`，删除倒数第 2 个节点：最后 `fast` 停在 5，`slow` 停在 3，所以删除 4。

当 n 等于长度时，`slow` 最终停在 `dummy`，自然完成删除头节点。

**先走几步必须与停止条件配套。** 另一种写法是 fast 先走 n + 1 步，再同时移动到 `fast == nullptr`。不要混用两种写法的步数和条件。

如果使用统计长度的方法：从 `dummy` 出发走 `size - n` 步到前驱；从 `head` 出发则是 `size - n - 1` 步，但必须另行处理删除头节点。

## 6. 相交链表：对齐到尾部的距离

相交是两条链表共用同一个节点，从该节点开始，后续也是同一段链表。以下两个值为 8 的位置画成同一个节点，才表示相交：

```text
A: 4 → 1 ───────┐
                 ↓
                 8 → 4 → 5 → nullptr
                 ↑
B: 5 → 0 → 1 ───┘
```

今天的实现先统计长度，A 长度为 5，B 长度为 6，所以 B 先走一步。之后同步移动，第一次指针相等的位置就是公共节点 8。

原因是：公共尾部长度相同，两条链表的总长度差就等于独立前缀的长度差。长链表先走掉这个差值后，两者到交点的距离相同。不相交时返回 `nullptr`，空链表也能处理。

时间复杂度为 `O(m + n)`，额外空间为 `O(1)`；当前长度法只适用于无环链表。

## 7. 环形链表：相遇节点与入口节点

第一阶段使用一快一慢两个指针：

```cpp
while (fast != nullptr && fast->next != nullptr) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) {
        // 有环，开始寻找入口
    }
}
```

必须先移动再比较，不能因为初始时两者都等于 head 就判定有环。进入环后，fast 每轮相对 slow 多走一步，所以会在有限步内追上 slow。

条件从左到右检查；若 `fast == nullptr`，`&&` 右边不再执行。`fast->next->next` 的结果允许是 `nullptr`，这里要求有效的是 fast 及其下一节点。

今天的连接关系是：

```text
1 → 2 → 3 → 4 → 5 → 6 → 7 → 8
            ↑                 │
            └─────────────────┘
```

| 已移动轮数 | slow 的节点值 | fast 的节点值 |
| --- | --- | --- |
| 0 | 1 | 1 |
| 1 | 2 | 3 |
| 2 | 3 | 5 |
| 3 | 4 | 7 |
| 4 | 5 | 4 |
| 5 | 6 | 6 |

第一次相遇在 6，而入口是 4。第二阶段让一个指针从头节点出发，另一个从 6 出发，两者都一次走一步：

```text
从头出发：1 → 2 → 3 → 4
从相遇点：6 → 7 → 8 → 4
```

为什么这样一定能找到入口？设头节点到入口需要 a 步，环长为 L，第一次相遇时 slow 总共走了 t 步。

1. fast 走了 2t 步，比 slow 多走 t 步。它们在环中同一节点相遇，多走的距离必定是完整圈数，因此 `t = kL`。
2. 从头出发的指针再走 a 步，正好到入口。
3. 从相遇点出发的 slow 再走 a 步，累计走了 `t + a` 步，扣除入环前的 a 步，在环中共走了 t 步。因为 t 是环长的整数倍，它也正好回到入口。

因此，两者会在入口相遇。a 可以为 0，对应入口就是头节点；环长可以为 1，对应单节点自环。

整个算法时间复杂度为 `O(n)`，额外空间为 `O(1)`。两阶段并不会相乘成 `O(n²)`；它们的工作量相加，仍然是线性级别。

## 8. 复杂度与使用场景

下表讨论单链表，n 表示链表长度；额外空间不包含原有节点本身。

| 操作或算法 | 时间复杂度 | 额外空间 | 条件或注意事项 |
| --- | --- | --- | --- |
| 按索引访问节点 | `O(n)` | `O(1)` | 需要从头逐个查找 |
| 头部插入或删除 | `O(1)` | `O(1)` | 删除时头节点须存在 |
| 已知前驱后的插入或删除 | `O(1)` | `O(1)` | 不包含寻找前驱的时间 |
| 按索引插入或删除 | `O(n)` | `O(1)` | 定位前驱通常需要遍历 |
| 尾部插入 | `O(n)` | `O(1)` | 维护尾指针后可降为 `O(1)` |
| 迭代移除元素、迭代反转 | `O(n)` | `O(1)` | 递归版本额外空间为 `O(n)` |
| 删除倒数第 n 个节点 | `O(n)` | `O(1)` | 固定间距双指针法 |
| 两条链表求交点 | `O(m + n)` | `O(1)` | 无环链表的长度对齐法 |
| 检测环并找入口 | `O(n)` | `O(1)` | 快慢指针法 |

“链表插入删除都是 O(1)”不准确，必须区分寻找位置和修改连接。单链表即使维护了尾指针，删除尾节点通常仍要找前驱，需要 `O(n)`。

`vector` 适合按下标访问和连续遍历；链表适合在已经定位的位置附近调整连接。链表不要求连续内存，但有指针存储和分散访问的开销，实际使用时不一定比 `vector` 快。C++ 标准库的 `std::forward_list` 是单链表，`std::list` 是双向链表。

## 9. 内存、边界与复习重点

- 查询可能返回 `nullptr`，使用 `result->val` 前先判断 result 是否非空。
- 使用 `new` 创建的节点，要有明确的释放责任。局部指针离开作用域，不会自动释放它指向的动态节点。
- 当前 `ListNode` 只有普通指针成员，销毁一个节点不会自动销毁后继节点。无环链表可保存 next 后逐个 delete；有环链表应先断环；相交链表的公共部分只能释放一次。
- 9 月 8 日的 `addAtIndex` 在检查非法索引之前执行 new，提前返回时会泄漏；应先检查边界，再申请节点。链表类目前还缺少释放全部节点的析构函数，这部分需要继续学习。
- 每题至少考虑空链表、单节点、头部、尾部、查找失败或全部被删除。环题再补上无环、入口在头节点、入口在中间、单节点自环。

三个值得自己回答的问题：为什么求交点时先走长度差？为什么删除倒数第 n 个节点时 slow 停在前驱？为什么环内第一次相遇后，要改成两个指针都走一步？能够根据起点、距离和停止条件解释清楚，比只记住代码更有助于独立解题。
