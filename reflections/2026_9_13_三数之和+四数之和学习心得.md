今天我练习了三数之和、四数之和，重点讨论了双指针的搜索范围、去重、剪枝和整数溢出，也学习了哈希值的基本含义。去重的边界是今天反复提问的部分，还需要结合具体数组复习。

1. **排序后固定部分数字，再用双指针搜索**

   三数之和固定一个数，四数之和固定两个数，再在后面的区间设置左右指针。和太大时右指针左移，和太小时左指针右移。每轮固定的数变化后，都要重新设置左右指针，不能沿用上一轮缩小后的右边界。找到一个答案后也不能直接退出，因为同一个固定值可能对应多个答案。

2. **去重是跳过重复的搜索，不是删除重复数字**

   `[-1, -1, 2]` 需要两个 `-1`，所以相同数字可以参与同一个答案。我需要区分“和前一个位置的数相同”与“这个值已经在本轮当过固定的数”。

   ```cpp
   // a 从 0 开始，第一个 a 必须保留
   if (a > 0 && nums[a] == nums[a - 1]) continue;

   // b 从 a + 1 开始，本轮第一个 b 必须保留
   if (b > a + 1 && nums[b] == nums[b - 1]) continue;
   ```

  找到答案后，可以先移动左右指针，再与刚才用过的值比较并跳过重复值；也可以先越过连续的重复值，再移动一步。两种写法的比较方向要对应。

3. **剪枝必须保证后面不可能再找到答案**

   四数之和不能只用 `nums[a] > target` 就退出。例如 `[-4, -3, -2, -1]` 的目标为 `-10`，虽然 `-4 > -10`，四数相加仍然能达到目标。加上 `nums[a] >= 0` 后，由于数组有序，后面的数也都非负，才可以确定总和不会再变小。

4. **扩大接收变量的类型，不等于扩大计算过程的类型**

   四个 `int` 相加可能溢出，应该让加法从一开始就使用 `long long`：

   ```cpp
   long long pairSum = 0LL + nums[a] + nums[b];
   long long sum = pairSum + nums[c] + nums[d];
   ```

   `long long sum = nums[a] + nums[b] + nums[c] + nums[d];` 仍然会先按 `int` 相加，再赋值。二级剪枝中的两数相加也要注意范围。`long` 不保证是 64 位，这里使用 `long long` 更稳妥。

5. **复杂度需要明确计算范围**

   三数之和的时间复杂度是 `O(n²)`，四数之和是 `O(n³)`。双指针部分只使用固定数量的变量，额外空间是 `O(1)`

6. **哈希值帮助定位数据，但不保证唯一**

   哈希函数把数据转换成哈希值，哈希容器再据此决定去哪个桶里查找。用“数字对 10 取余”作例子，`23` 和 `33` 都得到 `3`，这就是哈希冲突，因此还需要比较数据本身，不能只凭哈希值判断相等。

7. **数组、集合和 map 分别保存什么**

   我先按“需要保存什么”区分容器，再考虑是否需要排序。下面的例子使用 `std::` 表示标准库中的类型。

   | 类型 | 保存内容与访问方式 | 重复与顺序 | 适合的用途 |
   | --- | --- | --- | --- |
   | 数组 / `vector` | 按下标保存一串元素，如 `nums[0]` | 可以重复；保持存放的顺序，不会自动排序 | 顺序遍历、按位置访问、排序和双指针 |
   | `set` | 只保存键，也就是元素本身 | 元素不重复；默认按值从小到大排列 | 去重，并按大小顺序遍历 |
   | `unordered_set` | 只保存键，也就是元素本身 | 元素不重复；遍历顺序没有保证 | 快速判断某个值是否出现过 |
   | `map` | 保存“键 → 值”的对应关系 | 键不重复，值可以重复；默认按键排序 | 既保存对应信息，又需要按键顺序遍历 |
   | `unordered_map` | 保存“键 → 值”的对应关系 | 键不重复，值可以重复；遍历顺序没有保证 | 快速查找某个值对应的次数、下标等信息 |

   普通数组和 `std::array` 的长度固定，`vector` 的长度可以动态变化。`set`、`map` 默认的有序性来自比较规则；这里说的无序，是“不保证排序或插入顺序”，不是每次访问都会随机变化。

   我可以用下面三个问题帮助选择：

   - “第几个元素是什么？”——数组或 `vector`。
   - “这个元素有没有出现过？”——集合。
   - “这个元素出现几次，或者对应哪个下标？”——map 类容器。

8. **常见用法：按下标访问、判断存在、统计次数**

   ```cpp
   #include <vector>
   #include <unordered_set>
   #include <unordered_map>

   void examples() {
       // vector：保留元素及其位置，也允许重复
       std::vector<int> nums = {3, 3, 5};
       nums.push_back(7);           // 末尾添加元素
       int first = nums[0];        // 第一个元素是 3，注意下标不能越界

       // 集合：只关心某个值有没有出现过
       std::unordered_set<int> seen;
       seen.insert(3);
       seen.insert(3);             // 再插入一次，仍然只有一个 3
       bool exists = seen.find(3) != seen.end();
       seen.erase(3);             // 删除元素 3

       // map 类容器：保存“数字 → 出现次数”
       std::unordered_map<int, int> count;
       for (int x : nums) {
           count[x]++;            // 键不存在时先建立值为 0 的条目，再加一
       }
       // count 中有：3 → 2，5 → 1，7 → 1

       auto it = count.find(3);
       if (it != count.end()) {
           int times = it->second; // 出现次数为 2；it->first 是键 3
       }
   }
   ```

   `set` 和 `map` 也可以使用 `insert`、`find`、`erase`。map 类容器还可以用 `pos[x] = i` 保存“数值 → 下标”；如果键 `x` 已存在，赋值会覆盖原来的下标。

   我需要特别注意：集合不能用 `seen[0]` 取“第一个元素”。map 类容器中的 `count[3]` 也是按键 `3` 访问，并不是取第 4 个元素。只查找时用 `find()`；对 `map` 或 `unordered_map` 使用 `[]`，键不存在时会插入新条目。

9. **哈希表是什么，它与集合、map 有什么关系**

   哈希表是一种利用哈希函数组织数据、加快按键查找的数据结构。可以把它想成一排收纳桶：先根据键算出哈希值，再确定桶的位置，最后在桶里比较实际的键。

   ```text
   查找键 23 → 计算哈希值 → 确定桶 → 比较桶中的键 → 找到或确认不存在
   ```

   不同键可能落入同一个桶，需要处理冲突，所以不能认为“进了同一个桶就是同一个数据”。

   在 C++ 中，`unordered_set` 和 `unordered_map` 都是哈希容器：前者只存键，后者还存键对应的值。`set` 和 `map` 则通常基于平衡搜索树，并不是哈希表。因此，“集合”或“map”描述的是保存数据的形式，不能直接等同于“哈希表”。

   按键查找、插入和删除，哈希容器通常平均为 `O(1)`，最坏可能为 `O(n)`；`set`、`map` 的查找和普通单元素插入、按键删除通常为 `O(log n)`。这里的 `n` 是容器中的元素数量。

10. **什么时候用哈希表，什么时候用数组或排序**

    我遇到大量“是否存在”“出现几次”“对应哪个下标”的查询，而且不需要按键排序时，可以考虑哈希表，用额外空间减少重复查找。

    | 题目需求 | 常用选择 | 原因 |
    | --- | --- | --- |
    | 判断重复元素、求不重复的交集 | `unordered_set` | 只需要记录是否出现 |
    | 两数之和，返回下标 | `unordered_map<int, int>` | 保存“数值 → 下标”，查找 `target - x`；先查后存，避免使用当前元素两次 |
    | 四数相加，统计组合数量 | `unordered_map<int, int>` | 保存“两数之和 → 出现次数” |
    | 赎金信，题目只含 26 个小写字母 | `int count[26] = {};` | 范围小且固定，直接用 `字符 - 'a'` 作下标计数 |
    | 三数之和、四数之和，输出不重复组合 | 排序 + 双指针 | 排序后方便移动指针并跳过重复组合 |
    | 需要按键大小遍历 | `set` 或 `map` | 容器本身维护键的顺序 |

    数组按已知下标访问是 `O(1)`，但在未排序数组里查找某个值，通常仍要遍历，耗时 `O(n)`。用小数组计数属于直接按下标定位，不需要哈希函数；如果数值范围很大而实际元素很少，开一个覆盖整个范围的数组会浪费空间，哈希表通常更合适。
