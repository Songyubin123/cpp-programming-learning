# 2026 年 9 月 11 日集合与哈希表学习心得

## 今天完成的内容

今天我完成了“有效的字母异位词”的代码，并学习了用 `unordered_set` 求两个数组交集的思路。我进一步弄清了集合、哈希表、迭代器、范围构造和容器转换之间的关系。

## 用数组记录字母出现次数

判断字母异位词时，我使用：

```cpp
int count[26] = {0};
```

这个数组长度固定为 26，所有元素都初始化为 0，适合记录 26 个小写字母的出现次数。`s[i] - 'a'` 可以把字母映射到 `0～25` 的下标。

遍历两个字符串时，一个字符串对应位置加一，另一个对应位置减一。最后 26 个计数全部为 0，就说明两个字符串包含的字母及数量完全相同。先判断字符串长度是否相等，可以提前排除不可能的情况。

这道题的时间复杂度是 `O(n)`，额外空间复杂度是 `O(1)`，因为数组长度始终是 26。

## 三种集合容器

- `set`：元素不重复并自动排序，查找、插入和删除是 `O(log n)`。
- `multiset`：允许重复元素并自动排序，查找、插入和删除是 `O(log n)`。
- `unordered_set`：元素不重复，但不保证顺序；查找、插入和删除平均是 `O(1)`，最坏是 `O(n)`。

如果需要有序结果或范围查询，可以使用 `set`；如果只需要快速判断元素是否存在，并且不关心顺序，优先考虑 `unordered_set`。

## 哈希表的核心原理

`unordered_set` 底层使用哈希表。哈希表通过哈希函数把键转换成哈希值，再映射到某个桶中：

```text
key → 哈希函数 → 哈希值 → 桶
```

不同元素可能进入同一个桶，这叫哈希冲突。负载因子表示元素数量与桶数量的比例；负载因子过大时，容器会通过 `rehash` 增加桶并重新分配元素。

哈希分布均匀且负载率合理时，查找平均为 `O(1)`；如果大量元素发生冲突，最坏会退化为 `O(n)`。

## 迭代器和范围构造

迭代器可以理解为指向容器中某个元素的位置标记。`begin()` 指向第一个元素，`end()` 指向最后一个元素之后的位置，不能对 `end()` 解引用。

```cpp
unordered_set<int> nums_set(nums1.begin(), nums1.end());
```

这句代码使用 `[begin, end)` 范围创建集合，相当于把 `nums1` 中的元素逐个插入 `nums_set`，并在插入过程中自动去重。

```cpp
nums_set.find(num) != nums_set.end()
```

`find()` 找到元素时返回指向该元素的迭代器；找不到时返回 `end()`。因此上面的条件表示 `num` 存在于集合中。

```cpp
return vector<int>(result_set.begin(), result_set.end());
```

这句代码把结果集合中的全部元素复制到一个临时 `vector<int>` 中并返回。因为 `unordered_set` 不保证遍历顺序，所以返回的 `vector` 顺序也不固定。

## 两个数组交集的可复用思路

先把第一个数组放入 `unordered_set`，再遍历第二个数组并用 `find()` 判断元素是否存在。找到共同元素后放入另一个集合，利用集合不重复的特点完成结果去重，最后转换成 `vector` 返回。

这个方法的平均时间复杂度是 `O(n + m)`，额外空间复杂度是 `O(n + k)`，其中 `k` 是交集中不同元素的数量。

## 需要注意和继续复习的地方

- `end()` 不是最后一个元素，而是最后一个元素之后的位置。
- `unordered_set` 不能使用下标访问，也不能依赖遍历顺序。
- `find()` 返回迭代器，不直接返回布尔值。
重点是: 用unordered_set查询和增删效率是最优的效率最高!
今天需要记住的核心方法是：固定且很小的字符范围可以直接用数组计数；需要去重和快速判断元素是否存在时，可以使用 `unordered_set`；看到 `begin()` 和 `end()` 时，要把它理解为容器的完整半开区间 `[begin, end)`。
