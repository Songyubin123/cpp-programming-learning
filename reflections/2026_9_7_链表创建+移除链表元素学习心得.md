今天第一次系统练习了单链表，完成了链表节点的创建，并分别尝试用常规遍历、虚拟头节点和递归三种方法移除指定元素。

## 链表节点

我理解了 `struct ListNode` 是链表节点的类型

```cpp
struct ListNode {
    int val;
    ListNode* next;

    ListNode(int x) : val(x), next(nullptr) {}
};
```

`ListNode(int x)` 是构造函数，创建节点时会自动调用。冒号后面是初始化列表：`val(x)` 用 `x` 初始化节点值，`next(nullptr)` 表示新节点暂时不指向其他节点；最后的 `{}` 是构造函数体。

构造函数要求传入一个整数，因此应写成：

```cpp
ListNode* head = new ListNode(6);
```

不能直接写 `new ListNode()`，除非另外定义无参数构造函数。通过节点指针访问成员时使用 `->`，例如 `head->val` 和 `head->next`。

## 移除链表元素

常规遍历需要分两部分处理：先连续删除值等于目标值的头节点，再从新的头节点开始检查后续节点。访问 `cur->next->val` 前，必须先保证 `cur->next != nullptr`，否则可能访问空指针。

虚拟头节点可以把头节点和普通节点统一处理，减少单独判断头节点的代码。虚拟头节点不属于最终链表，使用完后要释放；也可以把它创建为局部对象，避免手动管理这部分内存。

三种方法都会检查每个节点一次，因此时间复杂度都是 `O(n)`：

- 常规遍历和虚拟头节点的额外空间复杂度是 `O(1)`。
- 递归会使用函数调用栈，额外空间复杂度是 `O(n)`。

## 指针传参与返回值

函数参数 `ListNode* head` 是值传递，函数得到的是头指针的副本。执行 `head = head->next` 只会改变函数内部的指针，不会直接改变 `main` 中的 `head`。

因此，删除头节点后必须接收函数返回的新头指针：

```cpp
head = solution.removeElements(head, 6);
```

## 递归理解

递归的核心是：每次只判断当前节点，把后面的链表交给同一个函数处理，并返回处理后链表的头节点。

```cpp
head->next = removeElements(head->next, val);
```

这句表示先清理当前节点后面的链表，再把结果接回当前节点。递归会先不断调用到 `head == nullptr`，然后从后往前返回并重新连接节点。


## 今日需要记住

链表删除的本质是修改 `next` 的指向。写代码时要重点检查空链表、头节点、最后一个节点，并在删除动态创建的节点时使用 `delete`，避免内存泄漏。
