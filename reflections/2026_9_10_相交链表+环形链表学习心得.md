## 相交链表：先对齐，再比较

我的做法是先分别统计两条链表的长度，再让较长链表的指针先走长度差，最后同时移动两个指针。

这样处理后，两个指针到链表末尾的距离相同。如果存在公共尾部，它们就会同时到达第一个公共节点；如果没有交点，最终返回 `nullptr`。

需要记住：相交指的是两个指针指向同一个节点，所以比较的是 `curA == curB`。两个不同节点即使 `val` 相等，也不算相交。统计长度后，我把指针重新指回了各自的头节点，这一步不能遗漏。

这道题的前提是两条链表都无环，否则统计长度的循环可能无法结束。时间复杂度为 `O(m + n)`，额外空间复杂度为 `O(1)`。

## 环形链表：先判断有环，再找入口

我的代码分为两个阶段：

1. `slow` 每次走一步，`fast` 每次走两步。如果相遇，说明存在环；如果 `fast` 或 `fast->next` 为空，说明无环。
2. 相遇后，让 `cur` 从头节点出发，`slow` 留在相遇节点。两个指针都每次走一步，再次相遇的位置就是环入口。

第一次相遇的节点不一定是入口。今天的例子是 `1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 4…`，第一次相遇在值为 `6` 的节点，最终找到的入口是值为 `4` 的节点。

循环条件 `fast != nullptr && fast->next != nullptr` 利用了 `&&` 的短路求值：只有 `fast` 非空，才会检查它的 `next`。时间复杂度为 `O(n)`，额外空间复杂度为 `O(1)`，这里的 n 是不同节点的数量。


## 今天对虚拟头节点的改进

我把原来的 `new ListNode(-1)` 改成了：

```cpp
ListNode dummy(-1);
dummy.next = head;
ListNode* fast = &dummy;
ListNode* slow = &dummy;
```

`dummy` 是对象，用 `.` 访问成员；`&dummy` 是它的地址，可以交给指针使用。函数结束时，`dummy` 自动销毁，不需要手动 `delete`。

返回 `dummy.next` 是返回仍然存在的链表节点的地址；不能返回局部对象自身的地址 `&dummy`。当前 `ListNode` 的销毁也不会自动释放 `next` 指向的节点。

## 需要继续改进的地方

- **结果打印前先判空。** 今天第 104 行直接读取 `cycleNode->val`，当前有环样例可以运行，但换成无环链表就会访问空指针。被注释的相交链表输出也有同样问题。
- **链表长度改变后，不能继续按原长度打印。** 昨天文件中的 `main()` 先反转得到 `5 → 4 → 3 → 2 → 1`，再传入 `n = 5`，实际删除的是头节点 `5`，结果为 `4 → 3 → 2 → 1`。第 83 行仍尝试读取第五个节点，会访问空指针；“删除倒数第 3 个节点”和原输出注释也没有同步更新。应改为遍历打印。
- **明确参数前提。** 当前删除倒数第 n 个节点的函数要求 `1 <= n <= 链表长度`。在题目保证该条件时成立；用于自己的程序时，需要决定如何处理非法 n。
- **补上练习程序的内存释放。** 今天 `new` 出来的节点没有释放。有环时要先断环，再逐个删除；相交链表的公共节点只能释放一次。
- **递归参数要对应函数定义。** 昨天心得中的 `reverse(temp, cur)` 对应的是 `(cur, pre)` 参数顺序；当前源码定义为 `reverse(pre, cur)`，因此正确调用是 `reverse(cur, temp)`。当前源码正确，旧心得片段需要按这个顺序理解。

写法上还可以统一使用 `nullptr`，并为 `std::abs` 显式包含 `<cstdlib>`。目前的 `while (diff--)` 在非负计数下逻辑正确，但 `while (diff > 0)` 配合循环内递减更直观。
